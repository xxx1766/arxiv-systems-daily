#### 1. The GPU Needs an Operating System
- 中文译名：GPU 需要一个操作系统：让闲置的 AI 硬件全速运转
- 链接：https://arxiv.org/abs/2611.08720
- 作者：Reza Nourai, Behnam Bastani
- 单位：OpenInfer（【工业界】）
- 分类：cs.DC
- 方向标签：A. 容器与运行时 (GPU 虚拟化 / 分时复用) & C. AI Infra (AI 加速器操作系统 / 显存优先级调度)
- 相关度：5/5

1. 核心贡献：
直面当今生成式 AI 基础设施中最触目惊心的算力浪费现象：**在大模型在线推理服务中，由于必须满足严苛的响应延迟，且每个生成步骤都在深度等待内存搬运，GPU 核心的数学运算单元（ALU/Tensor Core）实际有效忙碌时间仅占 6%~11%，其余近 90% 的时间完全在空转等待！**
作者提出，不能再把 GPU 仅仅当作一个被动接受批量指令的简单加速卡，而必须为 GPU 构建专门的「硬件级操作系统（GPU OS）」；并研发了基于单常驻核心（Resident Kernel）的轻量级调度原型，在保持高优先级服务延迟无损的前提下，将闲置计算资源借给后台离线作业。

2. 原理解析：
这就好比在上世纪 60 年代大型机出现之前，计算机只能单任务批处理，CPU 大部分时间都在等磁带读写，直到时间片轮转的操作系统诞生才释放了多任务潜力。
现在的 GPU 正处于这个史前阶段：
- **静态独占与排队阻塞**：传统 CUDA 流或 MPS 机制缺乏严格的抢占式调度与内存带宽 QoS，如果把训练等批处理任务塞进正在跑交互式推理的 GPU，在线服务的首字延迟（TTFT）和每 Token 延迟（TPOT）立刻雪崩；
- **单常驻核心调度（Resident Kernel）**：作者构建了常驻 GPU SM 上的微型调度器，如同一个极简的 OS 内核。它将复杂的计算图拆解为可被快速暂停（Pause）与恢复（Resume）的微指令块；
- **内存优先级与硬件分区倡议**：软件调度器协同硬件实现优先级抢占——当高优先级的推理 Token 需要访存时，后台低优先级任务瞬间挂起其内存总线占用，将 HBM 峰值带宽完整让渡给在线业务。

3. 关键结论：
在两款主流开源大模型的实测中，该系统能够将 GPU 整体算力利用率从低迷的 10% 左右拉升至数倍，且高优先级在线推理的延迟几乎没有受到干扰。同时，作者向各大芯片制造厂商（NVIDIA、AMD 等）提出了未来 AI 芯片必须原生支持的三大硬件特性诉求：毫秒级后台快速暂停指令、内存控制器层级的优先级队列、以及由硬件严密强制执行的物理空间分区。

4. 背景地位：
这是系统软件领域针对现代 AI 加速芯片体系结构的一次极具启蒙性与号召力的重磅发声。它标志着 GPU 资源管理正在从朴素的「容器/驱动级粗放挂载」迈向深水区的「片上多任务全功能虚拟化操作系统」时代。

5. 落地相关性：
对于在 Kubernetes 集群中管理数千张昂贵 H100/H200/B200 的云原生架构师而言，这是解决「GPU 算力闲置与成本高昂」矛盾的根本出路。利用类似技术在同一个 Pod 或物理 GPU 内安全混跑在线推理与离线轻量训练/微调，具有颠覆性的降本增效价值。

#### 2. AutoParallel: Composable, PyTorch-Native Automatic Parallelism for Production Training
- 中文译名：AutoParallel：面向生产级大模型训练的可组合 PyTorch 原生自动并行系统
- 链接：https://arxiv.org/abs/2611.08660
- 作者：Kaijian Wang, Sanket Purandare, Aditya Venkataraman, Will Constable, Ivan Kobzarev, 等（共 12 位作者，通讯作者：Francisco Massa）
- 单位：Meta Superintelligence Labs（Meta AI 基础大模型核心团队 / 【工业界】）、莱斯大学
- 分类：cs.DC
- 方向标签：C. AI Infra (分布式训练 / 4D 网格自动并行 / PyTorch 编译生态)
- 相关度：5/5

1. 核心贡献：
Meta AI 官方大模型训练基建团队的最新力作！训练前沿超大模型需要深度组合多种并行策略（数据并行 FSDP、张量并行 TP、流水线并行 PP、上下文并行 CP 以及专家并行 EP）。随着集群规模达到千卡万卡，手写这些并行配置（Hand-Written Recipes，如 TorchTitan 模板）不仅耗时费力，且往往严重拘泥于死板模式，无法针对特定硬件拓扑发挥出极限吞吐。
Meta 正式发布了 AutoParallel：业界首个完全基于 PyTorch 原生抽象的可组合自动并行规划器，能在大规模训练计算图上联合搜索最优切分方案，并生成完全标准、可复现、可人工检查的普通 PyTorch 代码，彻底消除独立复杂运行时的依赖。

2. 原理解析：
这就好比在 Kubernetes 集群中调度极其复杂的微服务拓扑：如果运维人员手动为每个 Pod 配置静态亲和性、容忍度和反亲和性，遇到机架跨交换机带宽不均时极容易配置出错。
AutoParallel 的破局之道：
- **全局统一联合搜索**：在 PyTorch 导出的计算图（FX Graph / Dynamo 捕获）上，将张量分布（DTensor）与操作算子作为联合优化问题，算法能够在跨数据中心、跨机架、跨 NVLink 的 4 维设备网格（4D Device Meshes）上自动寻找兼顾通信量与内存占用的全局最优解；
- **无缝原生代码生成**：传统自动并行系统（如 Alpa 或某些专有框架）往往需要维护一套极其庞大的独立 C++ 运行时，难以融入生产环境。AutoParallel 搜出的策略直接输出为标准的 `torch.distributed` 原生 API 调用；
- **人机协同可组合性**：支持用户将特定专家模块或动态控制流锁定为人工作业，而在标准密集 Transformer 层上全权交由算法自动搜索，提供了绝佳的生产工程灵活性。

3. 关键结论：
在涵盖稠密模型（Dense）、混合模型（Hybrid）以及 MoE 架构的多种大模型上，在由多达 128 张 NVIDIA H100 GPU 构成的 4 维网络网格集群中实测：AutoParallel 在大部分场景下均匹敌甚至超越了资深分布式系统专家精心手工调优的 TorchTitan 配方，训练吞吐提升高达 **18.3%**，并自主发现了多项人类专家以往从未写过的非对称混合并行新模式。相关代码已在 GitHub 完全开源。

4. 背景地位：
PyTorch 官方分布式团队在分布式训练自动化领域的里程碑式飞跃。它意味着大模型分布式训练正从依赖少数顶尖工程师手调的「手工作坊时代」，大步迈向算法数学规划与编译器协同的「全自动工程时代」。

5. 落地相关性：
对于正在搭建大模型预训练与持续微调集群的 Infra 团队而言，AutoParallel 是开箱即用的核武器。它免除了工程师在不同机型（如 8 卡 H800 vs 8 卡 H100 vs RoCE/InfiniBand 混合网络）之间痛苦调整并行维度的繁重负担，大幅缩短模型上云训练的研发周期。

#### 3. Aegis OS: A Transactional Multi-Tenant Operating System Runtime for Eliminating Authorization Fatigue in Autonomous Coding Agents
- 中文译名：Aegis OS：面向自主代码生成智能体消除授权疲劳的事务型多租户操作系统运行时
- 链接：https://arxiv.org/abs/2611.08516
- 作者：Hui Zhao
- 单位：Heurion Research
- 分类：cs.OS, cs.CR, cs.MA, cs.SE
- 方向标签：A. 容器与运行时 (Agent 沙箱运行时 / 事务快照与隔离) & B. 编排与调度 (多 Agent 工作空间合并与调度)
- 相关度：5/5

1. 核心贡献：
直面当下火爆的自主编程智能体（如 Google Antigravity、Anthropic Claude Code、OpenAI Codex CLI）在宿主机与云端执行时的「安全-自主权两难困境（Security-Autonomy Dilemma）」：若开启逐操作人类确认，用户面临严重的授权疲劳，动辄几百次确认打断心流；若开启完全自主免确认，智能体极易误删文件、泄露 `$HOME` 私钥、执行恶意命令或破坏代码仓库。
设计了 Aegis OS：首个面向代码智能体的轻量级事务型多租户操作系统运行时。通过高效的写时复制（CoW）文件系统快照、LCS 3-Way 智能合并引擎以及基于会话租约的隔离门控，在消除 90% 以上人工弹窗确认的同时，实现严格的安全攻防拦截与并发冲突自动消解。

2. 原理解析：
在云原生容器体系中，这相当于为每个智能体的工作空间注入了一个纳秒级快速分支的 Git + 容器沙箱运行时：
- **瞬时工作区克隆（Instant Workspace Forking）**：利用现代文件系统（macOS APFS 或 Linux btrfs/OverlayFS）的 Reflink 特性，克隆一个包含 1000 个文件（78.1 MB）的完整代码库仅需 6.3 毫秒（比 `cp -cR` 快 16 倍），让智能体在完全独立的隔离事务分支中随意执行编译、安装依赖和改写代码；
- **智能 3-Way 差异合并（Diff3 Engine）**：只有在智能体准备将更改提交（Commit）回宿主机时，才触发一次性的批处理审计。系统内置基于最长公共子序列（LCS）的 Diff3 合并引擎与可选的沙箱预提交语义验证门禁（`verify_cmd`）；
- **全方位攻防拦截**：通过深层拦截过滤，彻底封锁针对自定义凭证路径窃取、构建系统投毒、同域 L7 混淆代理（Confused-Deputy）及敏感数据外发（DLP）等恶意攻击。

3. 关键结论：
在 50 条受控轨迹（1500 次工具调用）与 52 个真实编程智能体真实日志（28,087 次工具调用）中，Aegis OS 将人类确认提示频次断崖式降低了 **90.7% 至 99.88%**；在涵盖 8 大类的 80 种端到端恶意对抗攻击下，Aegis OS 将攻击成功率从基准的 100.0% 彻底压制到 **0.0%**；同时完美保持了 100% 的多智能体不相交修改，并准确捕获了 10/10 的重叠行冲突与 10/10 的语义级代码冲突。

4. 背景地位：
大模型智能体落地工程化中的标志性成果。首次跳出单纯在 LLM Prompt 上加安全护栏的脆弱软件做法，自底向上从操作系统内核与文件系统事务切入，为 Agent 赋予了真正的工业级安全生产环境。

5. 落地相关性：
对于正在企业内部部署 Coding Agent、自动化代码审查微服务、或基于 Kubernetes Pod 搭建大规模并发智能体沙箱池的架构师而言，Aegis OS 的架构设计提供了可以直接落地的范式，完美平衡了开发者的极致自主性与企业 IT 资产的数据安全性。

#### 4. MORTIS: Compiler-Guided KV-Cache Management for LLM Agent Programs
- 中文译名：MORTIS：面向大模型智能体程序的编译器引导细粒度 KV-Cache 管理系统
- 链接：https://arxiv.org/abs/2611.08638
- 作者：Xiaoyu Ma, Jayanaka L. Dantanarayana, Savini Kashmira, Baichuan Li, Lingjia Tang, 等（共 6 位作者，通讯作者：Jason Mars）
- 单位：密歇根大学（University of Michigan / 【知名实验室】）、Symbiote（【工业界】）
- 分类：cs.OS
- 方向标签：C. AI Infra (推理服务 / 编译-运行时协同 / 变量生命周期感知 KV Cache)
- 相关度：5/5

1. 核心贡献：
指出当前主流的大模型服务系统（如 vLLM、SGLang 等）在管理 KV-Cache 时存在一个粗糙的盲区：它们将每个请求的 Prompt 机械地切分为「可复用的通用前缀」和「不透明的局部后缀」，在粗粒度层面上统一管理；然而在智能体多轮协作程序中，Prompt 内部由各种不同的变量组件构成（如系统角色设定、工具列表、中间检索结果、局部推演草稿），它们被后续不同 LLM 调用复用的频率和生命周期存在巨大的**提示内异质性（Intra-Prompt Heterogeneity）**。
系统领域著名学者 Jason Mars 团队提出了 MORTIS：首创了编译器-推理服务协同设计的系统架构，通过在上层类型化智能体程序中提取变量数据流与生命周期，深度指导底层 KV-Cache 的重排、保留、逐出与异步预取。

2. 原理解析：
这就像编译器优化物理内存分配：如果把整个函数的所有局部变量当成一个不可拆分的黑盒，垃圾回收就只能等整个函数退出。但如果编译器知道变量 A 在第 2 步后就再也不用，而变量 B 会贯穿全程，就能提前释放 A 并把 B 锁在 L1 高速缓存中。
MORTIS 的核心三步曲：
- **静态编译器数据流分析**：分析生成 Prompt 的强类型函数调用图，将 Prompt 中的文本片段与程序级变量严格对应，准确识别出各个变量片段在整个智能体执行树中的共享跨度和生存周期；
- **Prompt 物理组件智能重排（Component Reordering）**：在不改变语言模型语义逻辑的前提下，利用注意力机制的可交换性，将全局长寿命的共享变量靠前排列，将局部短命变量推后，人为构造出更长、更稳定的前缀命中链路；
- **生命周期感知缓存决策**：底层推理引擎不再依赖死板的 LRU 规则，而是依据编译器传递的存活区间标签，对即将到期的块精准立即释放，对即将被调用的变量块提前触发后台预取。

3. 关键结论：
在涵盖复杂工具调用与多步推演的典型智能体工作负载下，针对开源主流基准进行实测：MORTIS 相比业内最强的大模型推理系统 SGLang，实现了最高 **1.99 倍的作业完成时间（JCT）加速** 以及高达 **1.97 倍的整体推理吞吐提升**（几何平均加速比分别达 1.45 倍与 1.49 倍）。

4. 背景地位：
大模型推理系统与程序语言编译优化深度交叉的开拓性研究。将 KV-Cache 管理彻底从「系统层事后盲目统计（LRU/LFU）」解放出来，提升到了「编译期事前全知规划（Compiler-Directed）」的新高度。

5. 落地相关性：

- **Perron 根临界状态**：系统存在明确的稳态转移界限，当到达率超过「全缺失承载极限」时，正反馈闭环锁死；
- **反直觉的排队调度**：传统贪婪的 FIFO 调度是加剧雪崩的罪魁祸首；必须依据会话返回的间隔预期，实施具有「会话容量软上限（Session Cap）」的有损准入控制。

3. 关键结论：
在两大主流推理引擎、两种主流 GPU 硬件以及不同开源模型的严格受控测试中，理论预测的临界转折点与实际系统雪崩时刻 100% 吻合。作者提出的轻量准入控制算法成功在不牺牲整体服务吞吐的前提下，彻底消除了突发脉冲导致的亚稳态缓存坍塌。

4. 背景地位：
大模型推理服务可靠性与排队理论方向的重磅理论奠基之作。为学术界和工业界深入理解 Agentic 复杂长程工作流对底层云原生推理集群的冲击提供了坚实的数学工具。

1. 核心贡献：
针对大模型服务 Prefill-Decode (PD) 分离架构中最核心的痛点——**跨节点传输庞大的 KV Cache 严重拖慢首字延迟（TTFT）**。以往的优化手段存在二元对立：要么走极端的数据压缩（如低比特量化，牺牲数值精度或引入量化计算延迟），要么走极端的重计算（Decode 端丢弃缓存重新跑 Prefill，浪费大量 GPU 算力）。
纽约大学学者提出了 ReKV：打破传统的非此即彼选择，创造性地将「量化前缀传输」与「解码端后缀重计算」在时间轴上深度重叠，实现了网络传输与流水线计算的完美隐藏。

2. 原理解析：
这就好比在跨国搬家时：如果把所有家具（全部历史 KV Cache）全走昂贵的空运（高带宽 RDMA），运费与吞吐吃不消；如果家具全扔了到当地重新打一套（全量重计算），工人又累得半死。
ReKV 的精巧解耦策略：
- **前缀量化与边界状态（Boundary State）打包**：仅对前面的绝大部分历史 Token 进行高吞吐的 Q8/FP8 快速量化传输，同时仅保留一个高精度的 BF16 边界激活向量；
- **传输与重计算完全重叠（Overlap Pipeline）**：在庞大的前缀张量正在跨节点网卡之间搬运（In-Flight）的几毫秒空隙中，Decode 端的 GPU 立即以极轻的计算代价，利用边界状态在本地并发重新推演最后的少量后缀 Token；
- **网络带宽自适应决策**：依据当前提示词长度与节点间实际互联带宽，动态计算最经济的切分断点。

3. 关键结论：
在跨节点 NVIDIA H100 集群上，针对 Qwen2.5-7B、Qwen2.5-3B 及 Qwen3-8B 展开标准评测：对于 8K 上下文的请求，ReKV 相比传统的全量 BF16 传输将网络移交延迟大幅降低了 **2.36 倍、2.84 倍至 3.65 倍**！且性能全面优于纯传输或纯重计算方案；在真实大模型推理闭环中，端到端首字响应时间缩短了 1.16~1.63 倍。

4. 背景地位：
大模型 PD 分离网络数据面传输优化的精细化创新之作。为克服跨主机以太网与 InfiniBand 带宽瓶颈提供了极具工程优雅感的系统级方案。

5. 落地相关性：
对于正在自建基于 vLLM / Mooncake 等具备 PD 分离能力的分布式推理平台的团队，ReKV 提供了一种无需改动底层物理网络、仅靠上层软件调度即可大幅压降 TTFT 的轻量级高收益手段。

#### 11. ResServe: Accurate and Efficient FP4 LLM Inference with Residue Compensation
- 中文译名：ResServe：基于残差补偿的高精度低延迟 NVFP4 大模型推理系统
- 链接：https://arxiv.org/abs/2611.08713
- 作者：Shuo Rong, Ruibo Fan, Jiawen Wen, Xiaowen Chu（通讯作者：Xiaowen Chu）
- 单位：香港科技大学（广州）、香港科技大学
- 分类：cs.DC
- 方向标签：C. AI Infra (算子与编译优化 / NVIDIA B200 NVFP4 / 低比特高精度推理)
- 相关度：4.5/5

1. 核心贡献：
针对以 NVIDIA Blackwell (B200) 为代表的新一代 AI 芯片全面引入的原生 4 位浮点格式（NVFP4）展开深度系统级算子重构。虽然全量 FP4 量化能将显存带宽与推理吞吐翻倍，但在复杂代码生成、多步推理等任务中容易引发明显的精度劣化；而混合高精度计算（如 FP8/BF16）又会显著拖慢推理速度。
香港科技大学团队研发了 ResServe：一种基于**残差补偿（Residue Compensation）**的高精度低开销 FP4 大模型推理框架。其核心洞察在于：在大模型 Decode 阶段常见的窄矩阵计算（Narrow Matrix Operations）中，GPU 的硬件计算单元往往存在微小的富余算力窗口，完全可以用这部分闲置算力在线弥补精度损失，同时保持极致性能。

2. 原理解析：
这就像在传输高清视频时，既不想传庞大的无损原图，又不想画面出现明显色块：
- **FP4 基底 + FP4 稀疏残差**：将激活值拆解为标准的 FP4 量化基底张量，以及一个代表量化损失的超轻量 FP4 补差残差；
- **片上无额外搬运融合（On-Chip Fusion）**：利用 GEMM 算子内部的空闲寄存器与 SRAM，在同一个算子内部直接并发计算主基底与残差的乘积并当场相加，完全杜绝了中间张量写回显存（DRAM）的额外 I/O 往返；
- **选择性补偿策略**：在线性感度高的关键注意力层和生成阶段全面开启补偿，而在 Prefill 大矩阵计算中选择性旁路，确保全局吞吐最大化。

3. 关键结论：
在 NVIDIA B200 真实硬件上使用 NVFP4 格式进行实测：ResServe 引入的高精度补偿带来的端到端延迟开销仅为极微小的 **3.4%**，相比 W4A8 混合配置将请求延迟降低了 **22.4%~53.3%**；在涵盖 5 个前沿模型的代码生成评测中，ResServe 的生成准确率相比原生未补偿的 NVFP4 推理平均提升了 **15.04%**（MXFP4 格式下提升高达 53.57%）。

4. 背景地位：
针对 Blackwell 新一代架构底层算子特性的先锋性实证研究。完美兼顾了工业界对 FP4 极致低显存占用与高业务精度的双重苛刻诉求。

5. 落地相关性：
对于即将采购或已在私有云部署 NVIDIA B200 加速卡、从事大模型服务化部署的 Infra 团队而言，ResServe 提供了一套可以直接集成进 TensorRT-LLM 或 vLLM 的高价值生产级算子参考。

#### 12. RPEG: Training Reasoning Language Models Scalably and Cost-Effectively
- 中文译名：RPEG：面向长思考推理大模型高可扩展与高性价比训练的图驱动分布式引擎
- 链接：https://arxiv.org/abs/2611.09207
- 作者：Maciej Besta, Leonard Schmidt, Pierre Pang, Patrik Okanovic, Robert Gerstenberger, 等（共 6 位作者，通讯作者：Torsten Hoefler）
- 单位：苏黎世联邦理工学院（ETH Zurich / 可扩展并行计算实验室 SPCL / 【知名实验室】）
- 分类：cs.DC, cs.AI, cs.CL, cs.LG, cs.PF
- 方向标签：C. AI Infra (强化学习后训练 / 分布式系统 / GH200 集群执行图编排)
- 相关度：4.5/5

1. 核心贡献：
由高性能计算领域世界级泰斗 Torsten Hoefler 团队研发！强化学习后训练（RLHF / PPO / GRPO）是打造如 DeepSeek-R1、OpenAI o1 等具备长思考链（Reasoning LLMs）大模型的绝对核心，但此类系统的训练流程极其冗长复杂：单步 RL 就耦合了生成采样、奖励模型打分、参考模型评估以及策略梯度更新等多个超大模型与异构执行阶段，传统框架（如 ReaL、verl 等）只能局部优化，导致大量显存闲置与跨节点通信停顿。
ETH Zurich 提出了 RPEG：业界首个建立在形式化执行图与跨层性能模型驱动之上的长思考大模型分布式训练引擎，并在 GitHub 完全开源。

2. 原理解析：
这就像在复杂的微服务网格中，如果各服务调用链路混乱、拓扑结构动态跳变，就必须引入全局拓扑编排器：
- **RPEG 抽象图模型**：将强化学习训练的复杂交互严格建模为一个多阶段有向执行图，统一涵盖机架级、节点级与 GPU 芯片级的计算、通信、显存与拓扑层次；
- **状态感知流水线协同**：打破 Actor 模型生成与 Critic 模型更新之间的粗暴同步等待，通过细粒度异步流与内存管道，将采样轨迹数据在各 GPU 之间以零拷贝方式流水化流动；
- **硬件拓扑亲和调度**：针对最新的 Grace Hopper (GH200) 超级芯片架构，充分利用 CPU-GPU 间的 NVLink-C2C 超高互连带宽，将海量长轨迹状态平滑安置在主机内存中。

3. 关键结论：
在搭载多达 256 张 NVIDIA GH200 GPU 的真实大规模训练集群上，RPEG 分布式引擎展现出惊人的线性扩展能力：相比当前业内顶尖的 ReaL 框架训练吞吐提升最高达 **2 倍**；相比广泛使用的开源 verl 框架，将单步训练延迟降低了高达 **2.48 倍**，同时将物理集群的整体硬件利用率拉升了整整 **30%**。

4. 背景地位：
大模型强化学习后训练（RL 后训练时代）系统工程的集大成之作。将经典 HPC 领域的图模型理论成功引入当下最炽手可热的推理大模型训练体系，展现出世界一流实验室深厚的系统设计底蕴。

5. 落地相关性：
对于正在搭建大规模强化学习推理大模型训练集群（如对齐 DeepSeek-R1 类推演管线）的平台团队，RPEG 的全套开源架构提供了可以直接对标并迁移落地的现代分布式系统蓝图。

### 今日趋势小结

纵观 2026-11-10 系统方向全部 51 篇新文献，AI 基础设施与云原生体系的演进呈现出三个极具启发性的底层趋势：

1. **从「外围粗放挂载」迈向「芯片级操作系统」与「硬件原生深度调度」**：
   OpenInfer 的《The GPU Needs an Operating System》（论文 1）一针见血地指出了当前大模型服务化中最痛心的算力浪费——90% 的数学单元在等待中空转。未来的 GPU 必须拥有真正的片上轻量 OS，以支持常驻抢占与优先级 QoS；与此同时，Linux 内核最新的 `sched_ext` (eBPF) 调度框架（论文 5）也为在主机端根据 AI 负载动态生成专属内核调度器打开了大门。软硬件边界正在以肉眼可见的速度重构。

2. **生产级大模型训练基础设施进入「全自动规划」与「长思考 RL 编排」新纪元**：
   Meta 官方开源 AutoParallel（论文 2）标志着大模型分布式并行正式跨越了人类手写专家配方的瓶颈，基于 PyTorch 原生 DTensor 和 4D 设备网格实现了全自动策略搜索；而面对当前推理大模型（o1/R1）的强化学习训练狂潮，ETH Zurich 的 RPEG（论文 12）则将图调度与超算工程体系深度融合，把多阶段、多模型的复杂交互抽象为统一执行图，成倍压降了后训练的算力门槛。

3. **面向智能体长程交互的「运行时沙箱安全」与「细粒度 KV 缓存感知」成为显学**：
   随着自主编程智能体的大规模落地，Aegis OS（论文 3）通过秒级文件系统事务克隆与并发合并，在 OS 层面彻底攻克了授权疲劳与安全防护的顽疾；而在底层推理服务层面，MORTIS（论文 4）从编译期变量生命周期指导缓存管理、Nebula（论文 6）在小红书实现分布式位置无关缓存复用，以及 Iowa State（论文 9）严密证明的 Prefix Cache 雪崩坍塌更新律，无一不在揭示：下一代 AI 推理集群必须具备深刻的应用语义与智能体工作流感知能力。
